# Context and Guidelines for AI Agents

## Language

This repository is written entirely in **English**: code, comments, configuration, documentation (`README.md`, `docs/`), commit messages, patches, scripts, workflows, and operator-facing runtime output (logs, `echo` messages, CLI errors, test output).

Chat communication with the operator follows the language the operator uses.

## Building

This repository repackages upstream Hermes Desktop: a pinned upstream (`upstream.lock`) plus `patches/`. The procedures in `docs/` are normative:

- `docs/updating-upstream.md`: bump upstream, rebase, change or add a patch.
- `docs/build-github-actions.md`: build and release through the workflow.
- `docs/build-local.md`: build on a Windows machine.
- `docs/usage.md`: what users are told about data, upgrades and gateways; keep it in step with the patches.

In particular:

- The Windows package is built on Windows: through the GitHub Actions workflow by default, or locally on Windows only if the operator asks for it. Never cross-build it from Linux or WSL, and never install Node or other build tooling on the operator's machine without being asked.
- Patches are generated by `scripts/refresh-patches.sh` from commits in `./upstream`; never hand-edit a `.patch` file.
- Show the operator the diff of `patches/` before committing a rebased or new patch.

## Commits

- Messages always in **English**.
- **Conventional Commits** format: `type: concise subject` (subject up to ~72 characters).
- Valid types: `feat`, `fix`, `docs`, `refactor`, `chore`.
- Subject and body in the imperative mood, describing what the commit does: `add`, `fix`, `update`, `remove`, `refactor`, `document`.
- Body required, with a short paragraph summarizing the goal of the change and a bullet list describing the changes made.
- Before running `git push`, present the proposal and wait for explicit operator approval.
- Never create or push a tag without explicit operator approval: a `v*` tag publishes a public GitHub Release.
- Use explicit files in `git add`; never broad staging like `git add .`.
- If there are files unrelated to the task outside staging, ask the operator what to do. Never mention pending files in the commit message.
- **NEVER** add AI authorship or attribution trailers (e.g. `Co-Authored-By`, as Claude Code inserts by default), regardless of the tool in use.
